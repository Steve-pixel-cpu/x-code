## 给 x-code 补上"精准编辑"能力（对标 Claude FileEditTool + FileStateCache）

### 根因
x-code 写类工具只有 `write_file`（整文件覆盖），没有编辑工具。模型改一处只能整写，偷懒写一行就毁掉整个文件（本次 index.html 事故）。纯提示词治不了——缺的是工具。

### 改动 1：新增 `edit_file` 工具（字符串替换）
- 参数 `{path, old_string, new_string, replace_all?}`
- 写前校验管线：文件必须存在；old_string 必须存在；多处匹配且未 replace_all → 报错并报匹配数；old == new → no-op 报错；**stale 检查**（见改动 2）
- 返回 OK 摘要 + unified diff meta（复用现成 `_unified_diff` + `ToolOutput.with_meta`，前端 diff 卡片直接可渲染）

### 改动 2：FileStateCache（读后状态记录，三工具共享）
- `tools.py` 模块级 `_FILE_STATE: dict[绝对路径 → 内容 sha256]`（锁保护；跨会话共享方向保守，注释说明）
- `read_tool` 读取时记录（含分页读——它本来就整读再切窗）；统一用 `errors="replace"` 口径算 hash
- `edit_file`/`write_file` 写前比对磁盘当前 hash vs 记录：不一致 → 拒绝 "File has been modified since read. Read it again."
- 写成功后更新记录；存 hash 不存内容，内存无压力

### 改动 3：`write_file` 收紧
- **覆盖已存在文件必须先 read 过**（state 有记录）：未读 → 拒绝并提示 "Read it first, or use edit_file for targeted changes"
- 新文件创建不受限；stale 检查同 edit_file
- "写一行毁全文件"路径就此堵死：要么没读被拒，要么读过且写的是完整新内容

### 改动 4：接线与提示词
- `main.py`：新 spec（含防误用描述）、`TOOL_SPECS` 追加、`build_registry` 注册、`TOOL_REQUIREMENTS["edit_file"] = WORKSPACE_WRITE_MODE`
- `prompt.py` 工具段加一条：局部修改优先 edit_file；write_file 仅用于新文件或读完后的整体重写
- PURE_READ_TOOLS 不变（edit_file 天然按变异处理，推进护栏变异序号）

### 改动 5：测试
- 新建 `tests/test_edit_file.py`：基本替换+diff、不存在报错、多匹配/replace_all、no-op、未读先改拒绝、未读先写拒绝、新文件放行、外部修改后 stale 拒绝、分页 read 建档
- 更新既有直接 write_file 的测试（test_runtime/test_plan_mode 等需先 read 再写）

### 不做
- 收缩启发式（新内容远小于旧内容即拒绝）——read-before-write 已堵死事故路径，启发式会误伤合法重写
- OS 沙箱、extglob 禁用等深水区（backlog 已记录）
